# EDA findings (numbers only, 2026-10-13)

Source of every number: `hidrometros eda` (`src/hidrometros/eda.py`) on the Kaggle download.

## Structure (questions 1.1, 1.2)
- `data/WaterMeters/` has `images/`, `masks/`, `collage/` (1244 `.jpg` each) and `data.csv` (1244 rows). All 1244 images and 1244 masks decode; no file is missing against `data.csv`.
- `data.csv` columns: `photo_name` (e.g. `id_53_value_595_825.jpg`), `value` (float, e.g. 595.825), `location` (string-encoded dict `{'type': 'polygon', 'data': [{'x','y'}...]}`, x/y normalized to 0-1).
- `images/` = full photos (913 at 1000x1333, 149 at 1333x1000, rest 1000x1778, 1778x1000, 1000x1349, 1000x2057). `masks/` = grayscale display masks (JPEG noise). `collage/` = overlay visualization of image plus mask, not a training input.
- Mask vs polygon agreement (IoU of the binarized mask and the rasterized polygon, 1244 rows): median 0.983, 5th percentile 0.964, min 0.936. Polygons have 4 (505), 6 (508) or 8 (231) points.
- Labels exist per image (one float `value` for the whole reading). There is no per-digit annotation; the 8 crops get their digit labels by position.

## Label source (question 2.1)
- `value` equals the value parsed from the filename (`value_<int>_<dec>`) in 1244/1244 rows; after the 5+3 normalization the two sources give the same 8-char label for all 1243 valid rows.
- `value` is a float, so trailing decimal zeros are lost (`21.86` means `21.860`). The filename has the same limitation: 128 filenames carry fewer than 3 decimal digits (87 with 2, 41 with 1). Decimals are right-padded to 3 and the integer part is left-padded to 5.
- Visual check on the rectified strips (about 170 strips viewed during the orientation audit with the label overlaid): the display agrees with the label wherever the reading is legible.
- Exactly 1 image does not fit 5+3: `id_664_value_45_2676.jpg` (4 decimals). It is also the only row absent from `splits.csv`, so the professor's split already excludes it. 1243 valid images.
- 36 valid images have decimals `000`. In a random sample of 24 of them, 22 displays have only 5 wheels (no decimal wheels at all), so 3 of their 8 label digits do not exist on the display (see `2026-10-13-orientation-audit.md` and the README answer 3.2).

## Digit prior (question 2.2)
Digit share over the 9944 crops: 0 = 35.69%, 1 = 10.09%, 2 = 7.81%, 3 = 7.83%, 4 = 7.02%, 5 = 6.81%, 6 = 6.42%, 7 = 6.23%, 8 = 6.16%, 9 = 5.93%.
Per position: position 0 is `0` in 1240/1243 images, position 1 in 1192/1243, position 2 in 393/1243. Positions 3-7 are close to uniform. Class 0 is the majority because of the zero-padded integer part.
